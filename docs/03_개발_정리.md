## 3. 사용자가 보는 것

### 3-1. 차 화면 (구매자, Pleos 내비 화면)

- **출발 전 브리핑**: 목적지를 잡으면 경로 위 관심 매물을 지도 번호·사진 핀 + 오른쪽 추천순 목록으로. 제외 이유(판매자 시간·2열 착석·배터리·이미 지남 등)도 함께. 정차 중엔 미리 요청.
- **고르면 바로 설명**(T33·T34): 목록 줄이나 핀을 누르면 "카시트 판매자 설명: … 상태는 …"을 읽어 주고, 정차 중엔 사진·글 요약·사진에서 본 상태 카드가 펼쳐진다. '들려주기' 버튼은 없다.
- **말하기**(T34): 왼쪽 레일 마이크 → 자유롭게 묻고 고른다. "카시트 흠집 있어?", "얼마야?", "얼마나 돌아가?", "트렁크에 들어가?", "배터리 괜찮아?", "판매자 믿을 만해?", "왜 안 알려줘?", "둘 중에 뭐가 더 싸?", "뭐 추천해?", "가는 길에 뭐 있어?". 행동은 셋뿐: "유모차로 할게"(경합 고르기), "응/들를게"·"캠핑의자 미리 요청해 줘"(요청), "아니/다음에"(거절). 자막에 질문·답이 뜨고 읽어 준다.
- **주행 중 알림**: 한 번에 하나, 추천 1위만, 회전 300m 전·방향지시등·조향 3.5°·제동 중엔 미루기. 차임 → "카시트, 12분 더, 트렁크에 쏙, 기준가보다 3만 원 싸요. 들를까요?" → 큰 버튼 또는 말("응/아니"). 비슷하면 경합("카시트? 유모차?"). 15초 뒤 닫힘.
- **거래 카드**: 요청 중 → 판매자 수락 → 경유지 추가(`addWaypoint` → `getWaypointInfo` 확인) → 가는 중(도착 예정 공유, 3분 전 "나오세요") → '판매자가 나오고 있어요' → 도착 → **현장 확인**(받았어요 / 안 살게요 전액 환불, 판매자 기다림: 다시 알리기·5분 뒤 '판매자가 안 나왔어요') → 다시 출발 → 목적지 결과 카드(정산·판매자 평가 별점).
- **정차 시트**: 목적지·관심사(등급 must/likely/near, 결제 수단 줄)·차종 고르기·현장 확인·결과.
- **디자인**: 어두운 지도, 유리 카드, 크라프트는 "지금 답할 것"(알림·경합·현장 확인)에만, 폰과 같은 글꼴(11-10부터 Asta Sans 부분집합)·lucide, 주행 중엔 알림 카드와 큰 버튼만(상세는 정차 뒤).
- **시뮬레이터**(브라우저): 가상 콘솔로 좌석·방향지시등·조향·브레이크·배터리·시간·음성 대답·말하기 입력·Gleo 호출을 흉내. `?device`면 실기기처럼 화면 가득.

### 3-2. 판매자 폰 (`/seller/`)

홈(받는 중/쉬는 중 한 문장, 잠깐 쉬기 1시간·오늘은 그만·다시 켤 때까지, 진행 중 거래 줄, 물건마다 '지나간 차 N대에 보였어요', 물건 판: 가격·시간·바로 확정·판매 완료·내리기·'차에서 이렇게 들려요') · **같이 올리기**(글 붙여 넣기 → 제목·가격·품목·크기 자동, 사진으로 크기 채우기(AI 키가 있을 때) 또는 품목 기본 크기, 60cm 넘으면 실측 확인, 지난 등록의 장소·시간·바로 확정 기본값) · **요청 전체 화면**(물건·도착 예정·차종·실을 수 있는지·구매자 가린 이름·수락·이번엔 어려워요·오늘은 그만 받을래요) · **만남 전체 화면**(곧 도착·도착·기다림, '지금 나가요' 한 번, '건넸어요', 구매자가 끝낼 수 있게 되기까지 남은 시간) · 거래·정산·원장·구매자 평가·현장 사진 · 알림 받기(웹 푸시) · 홈 화면 추가.

### 3-3. 구매자 폰 (`/buyer/`)

홈 '내 차' 준비 체크(결제 수단·관심 물건·차종) · 관심 물건(빠른 추가, 등급별 우회 시간·도착 배터리) · 거래 내역·상세(대금이 지금 어디 있는지, 시간순 기록, 판매자 평가, 현장 거절 뒤 사진) · 결제 수단(시연은 테스트 수단만, 카드 번호를 받지 않음) · 요청 제한 안내 · 홈 화면 추가.

### 3-4. 체험·시연 페이지

- **체험 페이지**(비공개 공유 페이지, v12): 차 화면 + 폰 + 가상 콘솔이 페이지 안 서버로 함께 움직인다. '자동 시연' 버튼(`?auto`)은 7단계(브리핑 → 출발 → 캠핑의자에 "아니" → 경합에 "카시트"·"응" → 판매자 수락·경유지 → 지금 나가요·도착·현장 확인 → 건넸어요·받았어요 → 목적지·평가)를 손으로 할 때와 같은 길로 저절로. 1단계에서 카시트를 골라 설명을 듣고 "카시트 흠집 있어?"도 묻는다.
- **시연 페이지**(링크 공개, v10): 10장면 영상 + 장면마다 쓴 Pleos SDK·서버 API·판단 기준 + SDK 판정표·검증 + 화면 모음(차 6장·폰 8장) + 3분 영상.

### 5-3. "대회가 말한 Pleos AI로 못 만드나"에 대한 답 (11-04 공식 문서 전체 확인)

Pleos가 **앱에 주는 AI는 세 가지**다 — ① Gleo AI 앱 연동(앱이 함수를 선언하면 Gleo의 LLM이 사용자의 말을 함수 호출로 바꿔 앱을 부르고, 앱의 콜백으로 최종 답을 만든다), ② SpeechToText, ③ TextToSpeech. **앱이 부를 수 있는 LLM·대화 API는 없다**(Gleo가 앱을 부르는 방향만 있다). 그래서:

- **귀와 입은 Pleos**: 말하기는 Pleos TTS, 듣기는 Pleos STT(둘 다 ON_DEVICE, 앱 등록 불필요). Gleo로 말하면 Gleo의 귀로 들어와 같은 조수로 간다("주행중고에 카시트 흠집 있는지 물어봐" → ASK_ABOUT_LISTINGS(question)).
- **매물을 아는 두뇌는 앱**: 규칙 조수, 서버에 키가 있으면 Claude. Gleo는 우리 매물·우회 시간·배터리를 모르니 어차피 앱이 답을 만들어야 한다.
- **Gleo 규약은 그대로 따른다**: 기능 3개, 설명은 영어·1~2문장·예시 없이, `APP_ACTION_RESPONSE`를 7초 안에(ASK는 AI를 3초만 기다리고 규칙으로), 앱이 한국어로 직접 읽어 주므로 `mode: silent` + `data`에 답(Gleo가 맥락을 이어 가게). Gleo가 직접 말하게 하려면 `mode: voice`로 바꾸기만 하면 된다(한국어 문장을 통제하려고 silent로 둠).
- **문서에 없는 건 기대하지 않는다**: `asking` 뒤 되묻기·재호출 규약, `invokeWord`의 정의, 에뮬레이터의 Gleo·STT 유무. 확인 대화는 앱 안에서 끝낸다.

## 8. 남은 일 (사람이 해야 하는 것)

1. **Pleos Connect 에뮬레이터 만들기**: Android Studio SDK Manager → SDK Update Sites에 `https://nexus-playground.pleos.ai/repository/raw-releases/connect-avd/2.x/crp-sys-img.xml` → Pleos Connect 이미지(2.1.0, API 34) → Automotive AVD(Cold boot, 4 GB). 켜지면 `apps\car-android\install.bat`(빌드는 이미 성공).
2. **에뮬레이터 확인** `API_MATRIX.md` 마지막 절 1~10 순서대로(트렁크 값·단위 → 내비 목적지 → 브리핑 → 알림 → 경유지 → 도착, Gleo Intent, STT '말하기'). 결과를 🧪 열에 적고 ↪ 대체 중 확인된 API가 생기면 교체.
3. `ANTHROPIC_API_KEY`를 넣고 서버를 켜서 **크기 추정·사진 상태·조수**를 실제 사진·말로 한 번.
4. **폰 실기기**: 같은 와이파이 `http://<PC IP>:8787/seller/`·`/buyer/`, 웹 푸시는 HTTPS(README '웹 푸시').
5. **제출**: 11-11에 공식 양식을 받아 02장을 채웠다(`docs/02_접수양식.md`, `tools/submission-form.py`). 01장 연락처와 04장 동의·서명은 참가자가 직접 쓰고 11/15 23:59까지 이메일로 낸다. 심사 자료·링크·첨부에는 이름·연락처·소속 없이.

## 10. 작업 원칙 (`CLAUDE.md`)

- Pleos SDK는 확인한 시그니처·권한·enum만(11-04부터 실제 SDK 바이너리 기준). 미확인은 `TODO(G0)`·API_MATRIX ❌/📄, 대체(↪)하거나 거절. 시그니처 확인 ≠ 에뮬레이터 동작 ≠ 실차. 스텁 컴파일은 실제 컴파일이 아니다. 못 한 검증은 "미실행".
- 구매자 위치·경로는 주행 세션 메모리에만. 차 쪽 실패로 끝난 거래는 구매자 신뢰도에 넣지 않는다.
- 문구는 한국어, 짧고 구체적으로, 억지 감성 없이, 조사는 `josa()`. 화면 문구는 실제 동작과 맞춘다(AI가 안 돌면 'AI'라 쓰지 않는다).
- 주행 중엔 알림 카드와 큰 버튼만, 상세는 정차 뒤.
- 기능 완료 = 서버 테스트 + 쓰는 사람의 화면 경로. 기획서 문장 대조는 SPEC_CHECK에.
- 차 화면은 `styles.css` 토큰·lucide·JHGO Sans, 바꾸면 1280×720·1920×720 캡처를 본다. 폰은 디자인 시스템·`kit.tsx`, 390px 캡처.
- 루틴: `npm test` · `typecheck` → 화면 바꾸면 `build:web` + `e2e` → 셸·브리지 바꾸면 `e2e:bridge` + 스텁 컴파일 → 체험 페이지 `build -w apps/demo` + `e2e:auto` + 같은 경로로 재게시 → 화면이 크게 바뀌면 영상 재녹화. 판단은 가이드, 진행은 STATUS에 한 줄씩.
