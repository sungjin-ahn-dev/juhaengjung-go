# STATUS

최종 갱신: 2026-11-03 (Asia/Seoul)

## 지금 되는 것

- **판매자 폰** (`/seller/`): 같이 올리기(붙여넣기 → 제목·가격·품목, 크기는 사진 AI(서버에 키가 있을 때) 또는 품목 기본 크기로 채우고 그렇게 표시, 60cm 넘으면 실측 확인), 가능 시간·자동 수락, 차가 요청하면 전체 화면(도착 예정·차종·실을 수 있는지·구매자 가린 이름), 수락·거절, 진행(오는 중·곧 도착·도착·구매자가 기다리고 있어요), 건넸어요, 정산·원장, 구매자 평가, 구매자가 남긴 현장 사진, 알림 받기(웹 푸시)와 홈 화면 추가.
- **구매자 폰** (`/buyer/`): 거래 내역과 판매자 평가, 현장 거절 뒤 사진 남기기, 관심사·등급별 우회 시간, 결제 수단(시연은 테스트 결제 수단만), 요청 제한 안내.
- **차량 화면** (`/car/`): 1280×720 내비 화면. 지도(주행 중 진행 방향 위, 정차 중 전체)에 추천 순서 번호 핀(정차 중엔 사진 핀, 겹치면 옆으로 비켜 선으로 잇기), 오른쪽 추천순 목록(정차 중: 사진·판매자 설명·우회 시간·경로상 거리·적재·기준가·미리 요청, 주행 중: 사진 없이 큰 글씨 3줄), 핀↔목록 선택 연동, TBT, 도착 예정·배터리, GO 패널(알림·경합·거래 단계), 정차 시트(목적지·관심사·현장 확인·결과 카드·차종 고르기). 현장 확인에서 판매자를 기다리는 동안 다시 알리기, 도착 5분 뒤 '판매자가 안 나왔어요'. 결과 카드에서 판매자 평가. 결제 수단이 없거나 요청 제한 중이면 알림을 띄우지 않고 목록 위에 이유. 3열 차는 3열 착석까지 적재 판단.
- **서버** (`services/api`): 매칭·브리핑·알림 억제·개인화·거래 상태 머신(판매자 미응대·다시 알리기·현장 사진 포함)·대금 보관과 정산(시연 원장)·신뢰도와 추천 점수의 판매자 신뢰(R)·요청 제한·결제 수단·실시간 알림(SSE)·판매자 웹 푸시(VAPID)·사진 크기 추정(Claude, 키가 있을 때)·SQLite 저장소·HTTPS(인증서를 주면).
- **차량 앱 셸** (`apps/car-android`): WebView + Pleos SDK 브리지. NaviHelper·Vehicle·TextToSpeech를 확인된 시그니처로 부르고, 미확인 기능은 확인된 API로 대체(`docs/API_MATRIX.md`).
- **체험 페이지** (`apps/demo`): 판매자 폰 + 차량 화면 + 가상 콘솔이 페이지 안 서버로 함께 움직인다. 공유 페이지로 게시: https://claude.ai/artifact/2KLb5hBdgHzuT1Bz844rLL (비공개, 공유는 페이지의 공유 메뉴에서).
- **기능별 시연 페이지**: 10장면 영상 + 장면마다 쓴 Pleos SDK·서버 API·판단 기준 + SDK 판정표·검증. https://claude.ai/artifact/JJmk8Fsj3NpaVY6r3z2ptz (비공개). 1~8은 체험 페이지 녹화(`tools/record-demo.ts`), 9~10은 브리지 계약 시험 녹화(`JHGO_RECORD=<폴더> npm run e2e:bridge`). 만드는 법은 README '시연 영상'.
- **기획서 대조**: 기획서 문장마다 구매자·판매자 화면 경로와 확인을 맞춘 표 `docs/SPEC_CHECK.md`.

## 미실행 (사람의 조치 필요)

1. **Android 빌드**: PC Android Studio에서 `apps/car-android` 열기 또는 `apps\car-android\build.bat` → `demoDebug`·`pleosDebug`. 오류가 나면 그 줄이 문서와 실제 SDK의 차이다(먼저 볼 곳: `PleosBackend.kt`의 `TripRequest`·`TripInfo`·`WaypointArrivedInfo` import, `TripRequest(poiSubId = null)`).
2. **Pleos Connect 에뮬레이터 확인**: `docs/API_MATRIX.md` 마지막 절 순서대로. 특히 addWaypoint 임의 좌표, onWayPointArrived, CarUxRestrictions, WebView 유무, 주행 중 화면 허용(distractionOptimized).
3. **폰 실기기**: 같은 와이파이에서 `http://<PC IP>:8787/seller/`·`/buyer/` (서버가 시작할 때 주소를 찍는다). 웹 푸시는 HTTPS 주소에서만 받으니 README '웹 푸시' 순서로 연다. 아이폰은 홈 화면에 추가한 뒤.
4. **사진 크기 추정**: `ANTHROPIC_API_KEY`를 넣고 서버를 켜서 실제 사진으로 한 번 확인(지금은 가짜 추정기 테스트만).

## 알려진 한계

- 경로 계산은 시연 지역 도로망(수원~송파)뿐이다. 실제 서비스는 같은 인터페이스(`RoutingProvider`)에 외부 길찾기 API를 붙인다. 에뮬레이터 시연도 이 지역에서 해야 매물이 경로 위에 잡힌다.
- 대금 보관·정산은 시연 원장이고 결제 수단은 테스트 수단뿐이다(실제 결제 대행 연동 없음, 카드 번호를 받는 화면도 만들지 않는다 — 실서비스는 결제 대행사 결제창).
- 판매자 웹 푸시는 HTTPS 주소에서만 된다. 체험 페이지(공유 페이지) 안에서는 서비스 워커가 안 돼서 열린 화면의 실시간 알림만.
- 사진으로 크기 추정은 서버에 API 키가 있을 때만. 없으면 품목 대표 크기로 채우고 '품목 기본 크기'라고 쓴다. 샘플 그림(SVG)은 추정에 쓰지 않는다.
- 트렁크 열림·닫힘('실으셨나요?')은 Door를 확인하지 못해 시뮬레이터에서만 나온다. 시연 순서·영상에서는 뺐다.
- 3열 좌석은 이름을 확인한 ROW_3_LEFT·ROW_3_RIGHT만 등록한다(ROW_3_CENTER 미확인).
- 실제 SDK 모드의 지도 경로 선은 NaviHelper가 경로 선을 주지 않아 서버와 같은 계산기로 그린 근사다.
