## 미실행 (사람의 조치 필요)

1. **Android 빌드**: PC Android Studio에서 `apps/car-android` 열기 또는 `apps\car-android\build.bat` → `demoDebug`·`pleosDebug`. 오류가 나면 그 줄이 문서와 실제 SDK의 차이다(먼저 볼 곳: `PleosBackend.kt`의 `TripRequest`·`TripInfo`·`WaypointArrivedInfo` import, `TripRequest(poiSubId = null)`).
2. **Pleos Connect 에뮬레이터 확인**: `docs/API_MATRIX.md` 마지막 절 순서대로. 특히 addWaypoint 임의 좌표, onWayPointArrived, CarUxRestrictions, WebView 유무, 주행 중 화면 허용(distractionOptimized).
3. **폰 실기기**: 같은 와이파이에서 `http://<PC IP>:8787/seller/`·`/buyer/` (서버가 시작할 때 주소를 찍는다). 웹 푸시는 HTTPS 주소에서만 받으니 README '웹 푸시' 순서로 연다. 아이폰은 홈 화면에 추가한 뒤.
4. **사진 크기 추정**: `ANTHROPIC_API_KEY`를 넣고 서버를 켜서 실제 사진으로 한 번 확인(지금은 가짜 추정기 테스트만).

## 알려진 한계

- 경로 계산은 시연 지역 도로망(수원~송파)뿐이다. 실제 서비스는 같은 인터페이스(`RoutingProvider`)에 외부 길찾기 API를 붙인다. 에뮬레이터 시연도 이 지역에서 해야 매물이 경로 위에 잡힌다.
- 대금 보관·정산은 시연 원장이고 결제 수단은 테스트 수단뿐이다(실제 결제 대행 연동 없음, 카드 번호를 받는 화면도 만들지 않는다 — 실서비스는 결제 대행사 결제창).
- 판매자 웹 푸시는 HTTPS 주소에서만 된다. 체험 페이지(공유 페이지) 안에서는 서비스 워커가 안 돼서 열린 화면의 실시간 알림만.
- 사진으로 크기 추정은 서버에 API 키가 있을 때만. 없으면 품목 대표 크기로 채우고 '품목 기본 크기'라고 쓴다. 샘플 그림(SVG)은 추정에 쓰지 않는다.
- 트렁크 열림·닫힘('실으셨나요?')은 Door를 확인하지 못해 시뮬레이터에서만 나온다. 시연 순서·영상에서는 뺐다.
- 3열 좌석은 이름을 확인한 ROW_3_LEFT·ROW_3_RIGHT만 등록한다(ROW_3_CENTER 미확인).
- 폰 글꼴(JHGO Sans)은 KS X 1001 한글 2,350자와 앱 글자만 들어 있다. 드문 글자(예: 이름의 '똠')는 기기 글꼴로 보인다.
- 매물 사진 자리는 시연용 평면 그림이다. 판매자가 실제 사진을 고르면 그 사진이 쓰인다.
- 실제 SDK 모드의 지도 경로 선은 NaviHelper가 경로 선을 주지 않아 서버와 같은 계산기로 그린 근사다.
