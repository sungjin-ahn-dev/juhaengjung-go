## 1. 서비스 개요 (아이디어 요약)

**짧은 판**
주행중GO!는 찜해 둔 중고 매물이 운전 경로나 지나는 지역에 있으면 알려 주고, 판매자 수락부터 경유지 추가까지 차 안에서 끝내는 차량용 중고 거래 앱이다. 구매자는 거래만을 위해 따로 나가지 않고 가는 길에 사고, 판매자는 실을 수 있는 차를 탄 구매자를 집 앞에서 만난다.

**긴 판**
구매자는 폰에서 관심 물건(키워드·찜)과 GO 등급(무조건 GO / 웬만하면 GO / 가까우면 GO, 등급마다 허용 우회 시간)을 정해 둔다. 차에서 목적지를 정하면 출발 전 브리핑이 이번 길 위의 관심 매물을 추천순 번호 핀과 목록으로 보여 주고, 주행 중에는 갈림길 전에 한 번에 하나만 음성으로 묻는다("카시트, 6분 더, 트렁크에 쏙, 기준가보다 3만 원 싸요. 들를까요?"). "응"이면 판매자 폰 전체에 요청이 뜨고, 수락하면 대금을 보관하고 내비에 "주행중GO! 픽업 · 카시트" 경유지를 넣는다. 도착 3분 전 판매자에게 "나와 주세요", 경유지 도착 이벤트로 "도착했어요"를 보내고, 정차하면 현장 확인 화면에서 "받았어요" 또는 "안 살게요(전액 환불)"로 끝낸다. 목적지에 도착하면 따로 다녀왔다면 걸렸을 시간과 실제로 늘어난 시간을 보여 주고 판매자를 평가한다. 판매자는 다른 앱에 쓴 글을 붙여 넣기만 하면 되고(제목·가격·품목·크기 자동), 큰 물건은 실측 확인, 거래 가능 시간과 바로 확정(자동 수락), 잠깐 쉬기를 둔다.

## 2. 문제 정의 (Pain Point)

- 구매자: 큰 물건(카시트·유모차·캠핑의자·가구)은 택배가 어렵고 동네 범위 밖 매물은 "일부러 가야" 해서 포기한다. 차로 매일 지나는 길 위에 그 물건이 있어도 모른다.
- 판매자: 큰 물건을 올리면 "차 있으세요? 트렁크에 들어가요?"부터 묻고, 약속을 잡아도 안 오는 사람이 있다. 동네를 지나가는 사람에게는 보이지 않는다.
- 기존 차량 커머스(GM Marketplace, Xevo 등)는 24시간 열린 제휴 매장을 전제로 하고, 중고 앱(당근·번개장터)은 이동 경로와 차의 적재를 모른다.

## 3. 차량특화성

**짧은 판**
폰은 내 경로·목적지·차종·좌석·배터리를 모른다. 주행중GO!는 차가 아는 신호로 "지금 들를 수 있고(경로·우회 시간), 실을 수 있고(차종·착석), 갔다 와도 되는(도착 배터리)" 매물만 고르고, 말해도 되는 순간(회전 전·방향지시등·조향·제동 아님)에만 한 번에 하나씩 말한다. 거래 확정은 내비 경유지로 이어지고, 상세 화면은 정차(CarUxRestrictions 해제) 뒤에만 연다.

**긴 판**
여정 10단계마다 차에서 읽는 신호가 하나씩 있다 — 모드(내비 상태), 후보(목적지·현재 위치), 우회(requestTrip·경유지), 에너지(도착 배터리 예측), 적재(차종·2열/3열 착석), 말할 때(TBT·방향지시등·조향각·브레이크·주행 제한), 약속(addWaypoint → getWaypointInfo 재확인), 만남(경유지 남은 시간·onWayPointArrived), 건네기(정차 판단), 마무리(주행거리계·편안한 길). 모바일 앱으로는 이 중 어느 하나도 같은 정확도로 만들 수 없다. 반대로 차 안에서 하지 말아야 할 것도 정했다: 둘러보기·채팅·흥정은 만들지 않고, 주행 중에는 카드 하나와 큰 버튼 둘, 정해진 단어("응/아니", 품목 이름)만 받는다.

## 4. 창의성·차별성

**짧은 판**
개인 간 중고 거래 + 실시간 수락 + 경로·적재 매칭을 한 흐름에 묶은 사례를 찾지 못했다. 구매자의 "일부러 가야 함"과 판매자의 "차 있으세요?"를 같은 매칭으로 푼다. 수락 시 대금 보관 → 현장 확인 → 정산으로 "약속하면 반드시 오는 구매자"를 만들고, 판매자는 기존 앱을 버릴 필요 없이 글을 붙여 넣어 같이 올린다.

**긴 판**
- 매칭 기준이 '동네'가 아니라 '경로·지역 × GO 등급 × 우회 시간 × 적재·에너지 여유'다. 점수가 비슷한 두 매물은 "카시트? 유모차?" 하나로 묻는다(경합).
- 개인화는 재학습이 아니라 "같은 품목을 다른 날 두 번 이상 지나쳤으면 덜 알린다"는 규칙 하나다.
- 판매자 신뢰(수락 뒤 취소·미응대·현장 불일치)를 추천 점수에 곱하고, 구매자 요청 제한(30일 3번 → 7일)으로 양쪽을 지킨다.
- 판매자에게는 도착 예정·차종·적재 판단만 보이고 구매자 위치·경로는 주행 세션 메모리에만 둔다.
- 다른 플랫폼 매물을 수집하지 않는다(법적 위험). 자체 등록 + 실측 확인으로 적재 판단의 정확도를 만든다.

## 5. SDK/API 사용 계획 (기술 활용성)

**원칙** — 차를 움직이기보다 차를 읽는다. 사용 신청 없이 바로 쓸 수 있는 Vehicle State·NaviHelper 조회 기능으로 핵심을 만들고, 준비 중인 SDK(음성·위치·제어)는 같은 인터페이스 뒤에 두어 열리면 구현만 바꾼다. 차종마다 지원이 달라도 깨지지 않게 `check…Capabilities`로 먼저 확인하고, SDK 호출이 성공했다고 끝내지 않고 `getWaypointInfo`로 반영을 재확인한 뒤에 판매자에게 확정을 알린다. 시그니처·퍼미션은 공식 레퍼런스(Vehicle SDK 2.3.2, NaviHelper SDK 3.0.5, TextToSpeech 3.3.1)에서 확인한 것만 쓴다.

| 단계 | Pleos SDK / API | 용도 | 퍼미션 |
|---|---|---|---|
| 모드 | NaviHelper `onNavigationStatus` | 경로 안내 중이면 경로 매칭, 아니면 지역 매칭 | 리스너 |
| 후보 | `getDestinationInfo`, `getCurrentLocationInfo` | 목적지·남은 시간·현재 위치 → 서버가 길 위 매물 계산 | NAVI_ROUTE |
| 우회·에너지 | `requestTrip` → `onTripInfo`(거리, eta, estimatedSocAtDest), `getWaypointInfo` | 매물까지 시간, 도착 배터리 15% 기준, 경유지 여유(최대 2) | NAVI_ROUTE |
| 적재 | Vehicle CarInfo, Seat `registerSeatOccupancy`(ROW_2·ROW_3) | 차종 → 트렁크 치수표, 착석 열은 접지 않음 | CAR_INFO, CAR_SEATS |
| 에너지 | EvBattery `getEvBatteryStateOfCharge`, Fuel | 지금 배터리·주행 가능 거리 | CAR_ENERGY |
| 말할 때 | `getTBTInfo`/`onTBTInfo`, TurnSignal, SteeringWheel, Brake, AAOS `CarUxRestrictionsManager` | 회전 300m 전·방향지시등·3.5° 이상 조향·제동 중 미루기, 주행 중 화면 제한 | NAVI_ROUTE, CAR_LIGHTS, CAR_DRIVE |
| 약속 | `addWaypoint`(출발 전이면 `requestRouteWithWaypoints`) → `getWaypointInfo` 재조회, `removeWaypoint` | 수락 뒤 경유지 추가와 반영 확인, 거래 뒤 해제 | NAVI_ROUTE_SEARCH |
| 만남 | `getWaypointInfo`(남은 시간), `onWayPointArrived` | 도착 3분 전 "나와 주세요", 도착 알림 | NAVI_ROUTE |
| 건네기·마무리 | CarUxRestrictions(정차), Odometer, `changeRouteOption(COMFORTABLE)` | 현장 확인 화면, 실제로 더 달린 거리, 깨지기 쉬운 물건이면 편안한 길 | CAR_DRIVE, NAVI_ROUTE_SEARCH |
| 음성 | TextToSpeech `speak`(ON_DEVICE, ko-KR); STT는 안드로이드 SpeechRecognizer로 대체 | 알림 문장 말하기, "응/아니"·품목 이름 듣기 | TTS_SERVICE, RECORD_AUDIO |
| 음성 비서 | Gleo AI App Schema(`assets/schema.json`, actionCalls 3개) + Intent·`APP_ACTION_RESPONSE` 규약 | "주행중GO에 유모차 관심 추가해 줘"(ADD_INTEREST), "들를게"(ANSWER_ALERT), "가는 길에 뭐 있어?"(SHOW_BRIEFING) — 결과는 영어 문장·데이터로 돌려주고 Gleo가 답함 | 스키마 검토 |
| 오류 | `onError(NaviErrorCode)` | 경유지 실패면 요청 취소(구매자 신뢰도 제외) | 리스너 |

**쓰지 않는 것** — Door 잠금 해제·앰비언트 조명(제어 SDK 준비 중, 보안), `VehiclePropertyIds` 직접 접근, 주차 브레이크·기어·속도(SDK에 없음).
**아직 확인하지 못한 것** — 에뮬레이터에서 `addWaypoint` 임의 좌표, `onWayPointArrived`, CarUxRestrictions 변화, Virtual Console 신호 반영, CarInfo 모델명, Door(트렁크), Fuel 주행 가능 거리, Pleos TTS 동작. 각각 대체 동작을 정해 두었다(기획서 11-5). 경로 선과 "들르면 몇 분 더"는 NaviHelper에 없어 서버가 외부 길찾기 API로 계산한다.

## 6. 사업성

**타깃** — 구매자: Pleos Connect 차량으로 매일 출퇴근·출장하는 운전자, 큰 물건 수요가 생기는 시기(육아·캠핑·이사)부터. 판매자: 큰 물건을 파는 개인(차 유무 무관).
**확보** — 판매자는 기존 앱을 그만둘 필요 없이 글을 붙여 넣어 같이 올린다(추가 비용 거의 없음). 구매자는 Pleos App Market에서 설치하고 백그라운드로 동작한다. 한 구간(예: 수원~송파)에서 매물·구매자 밀도를 먼저 만든 뒤 넓힌다.
**지속 이용** — 출퇴근 경로는 매일 반복돼 앱을 열지 않아도 알림이 생기고, 출발 전 브리핑이 목적지를 정할 때마다 여는 계기가 된다. 판매자는 한 번 팔아 본 뒤 다음 큰 물건도 같은 방식으로 올린다.
**예상 MAU(산식 + 1차 추정)** — 구매자 MAU = Pleos 탑재 차량 수 × 설치율 × 월 활성률. 플레오스 커넥트가 먼저 실린 그랜저·아반떼가 2026년 9월 한 달 1만 6천 대(8,898 + 7,305) 팔려 1년이면 약 19만 대, 4분기 투싼·2027년 기아 전 차종으로 넓어진다. 출시 12개월 국내 탑재 약 20만 대 × 설치율 5~10% × 월 활성 30~50% = 구매자 MAU 약 3천~1만(가정 명시, 설문·실데이터로 갱신). 판매자 MAU = 월 신규 등록 + 재등록, 수도권 출퇴근 축에서 월 수백 명으로 시작.
**수익(초기안)** — 성사 거래 수수료, 초기 확산 기간 무료.

## 7. 개발 현황과 산출물

- 핵심 로직(매칭·우회·적재·에너지·알림 타이밍·거래 상태·개인화)·서버·차 화면·판매자/구매자 폰 웹까지 끝까지 동작하는 프로토타입. 테스트 109개, 시뮬레이터 E2E 3부, 실제 SDK 모드(가짜 브리지) 계약 시험, 체험 페이지 자동 시연 통과.
- Android 셸(Kotlin, WebView + Pleos SDK 브리지)은 레퍼런스 시그니처 스텁으로 컴파일 확인. Pleos Connect 에뮬레이터·실차는 미실행(2차 PT 전까지 확인 항목 10개를 돌린다).
- 시연 영상 약 3분 한 편 + 장면별 10편. GitHub 저장소(소스, CI, `apk/`에 `팀명_주행중GO_release.apk` — 에뮬레이터 빌드 뒤 추가). 체험 페이지 한 파일('자동 시연').
- 2차 PT 시연 구성: Pleos Connect Emulator + Virtual Console(구매자 차) + 실제 폰의 판매자 웹 + 더미 매물. 음성 엔진이 안 되면 같은 장면을 화면 알림과 버튼으로.
