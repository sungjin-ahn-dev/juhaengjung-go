## 1. 서비스 개요

**주행중GO!**는 찜해 둔 중고 매물이 운전 경로나 지나는 지역에 있으면 알려 주고, 경유지 추가부터 판매자 수락까지 차 안에서 끝내는 차량용 중고 거래 앱이다. 구매자는 따로 나가지 않고 가는 길에 사고, 판매자는 실을 수 있는 차를 탄 구매자를 집 앞에서 만난다.

| 항목 | 내용 |
|---|---|
| 서비스명 | 주행중GO! (주행 중 + 중고 + GO) |
| 구매자 가치 | 동네 밖 매물까지, 거래만을 위한 별도 이동 없이 가는 길에 산다 |
| 판매자 가치 | 실을 수 있는 차만, 집 앞까지, 약속하면 반드시 오는 구매자. 우리 동네를 지나가는 사람에게까지 보인다 |
| 핵심 차량 기능 | 경로·적재 매칭 — 차가 아는 경로·도착 예정·차종·좌석·배터리로 "지금 들를 수 있고 실을 수 있는" 매물만 고른다 |
| 대상 | 구매자: 차로 이동하는 운전자 / 판매자: 큰 물건을 파는 개인 (차가 없어도 된다) |
| 플랫폼 | Pleos Connect(Android Automotive OS) 차량 앱(구매자) + 판매자용 모바일 웹 |
| 매물 확보 | 자체 판매자 등록. 다른 중고 플랫폼과 제휴하거나 매물을 수집하지 않는다 |

## 2. 문제 정의

중고 거래의 가장 큰 비용은 물건 값이 아니라 거래를 위한 이동과 조율이다. 이 비용은 구매자와 판매자 양쪽에 있다.

**구매자**
1. **일부러 나가야 한다.** 가구·유아용품·캠핑 장비처럼 큰 물건은 차로 가지러 가야 하고, 한 번 거래에 왕복 이동이 붙는다.
2. **좋은 매물은 동네 밖에도 있다.** 거주지 반경으로만 찾으면 더 싸거나 상태가 좋은 매물을 놓친다. 출퇴근길·출장길처럼 매일 지나는 경로는 탐색 범위로 쓰이지 않는다.
3. **허탕 위험이 있다.** 도착했는데 판매자가 없거나, 물건이 내 차에 안 실리거나, 사진과 다르다.
4. **운전 중에는 쓸 수 없다.** 채팅·흥정·송금 같은 폰 중심의 거래 과정은 운전 중에 쓸 수 없다.

**판매자**
5. **큰 물건은 "차 있으세요? 들어갈까요?"부터 시작한다.** 차가 없거나 안 실리는 사람과의 문답과 약속이 헛수고가 된다.
6. **노쇼와 현장 흥정이 있다.** 시간을 비워 두고 기다렸는데 오지 않거나, 와서 값을 깎는다.
7. **구매자가 동네 안 사람으로 한정된다.** 동네 기반 플랫폼은 동네 범위 안에서 매물을 보여 준다. 택배로 못 보내는 큰 물건은 동네 밖 구매자에게 닿기 어렵다.

## 3. 누구에게 무엇을 주나

| | 구매자 (차 안) | 판매자 (모바일 웹) |
|---|---|---|
| 찾기 | 출퇴근·출장 경로 위 동네 밖 매물을 알림으로 받는다 | 동네 사람뿐 아니라 우리 동네를 지나가는 운전자에게도 보인다 |
| 판단 | 우회 시간, 적재 가능 여부, 배터리 여유, 기준가 대비 가격을 앱이 계산한다 | 실을 수 있는 차에만 알림이 가서 "들어갈까요?" 문답이 없다 |
| 약속 | 판매자가 수락하면 내비에 경유지가 자동으로 들어간다 | 수락 순간 대금이 보관된다. 노쇼와 흥정이 없다 |
| 만남 | 판매자에게 도착 예정 시각이 자동으로 간다 | 도착 몇 분 전 "나오세요" 알림을 받고 집 앞에서 건넨다 |
| 보호 | 물건이 등록 정보와 다르면 현장에서 거절하고 전액 환불받는다 | 설명과 같으면 확인 후 정산된다. 수락 후 취소·노쇼는 구매자 신뢰도에 남는다 |
| 수고 | 운전 중에는 음성으로 "응/아니"만 한다. 말을 걸 때도 회전·차선 변경 중은 피한다 | 다른 앱에 올린 자기 글을 붙여 넣고 크기만 확인하면 등록된다. 기존 앱을 그만 쓸 필요가 없다 |

**한 줄 메시지**
- 구매자: 동네는 좁고, 길은 넓다. (모토 후보)
- 판매자: 큰 물건, "차 있으세요?"부터 묻지 않아도 됩니다. 실을 수 있는 차만 집 앞까지 옵니다.

## 6. 타깃과 페르소나

- **구매자:** 출퇴근·출장·주말 나들이로 매일 차를 타고, 중고 거래 경험이 있는 운전자. 육아·캠핑·이사처럼 큰 물건 수요가 생기는 시기의 운전자를 먼저 겨냥한다.
- **판매자:** 큰 물건을 팔려는 개인. 차가 없어도 된다. 이미 다른 중고 앱에 올린 사람도 같이 올릴 수 있다.

**구매자 페르소나 (시연용, 가명)**
- 김주행, 34세, 서울 송파 거주, 판교 출근, 육아 중. 전기 SUV를 탄다(시연용 가정).
- 아기 카시트와 유모차를 중고로 찾는 중. 동네 매물은 비싸거나 상태가 아쉽다.
- 이번 주는 수원 출장 중이다.

**판매자 페르소나 (시연용, 가명)**
- 박서연, 39세, 성남 판교 거주.
- 아이가 커서 카시트를 정리하려 한다. 평일 저녁에만 집에 있다.
- 다른 앱에도 올렸지만 "차 있으세요? 트렁크에 들어가요?" 문답과 노쇼에 지쳤다.

## 7. 기능 명세

### 7-1. 구매자 차량 앱 (Pleos Connect)

| 기능 | 설명 | SDK·API |
|---|---|---|
| 관심사 저장 | 키워드 또는 매물 찜. 찜할 때 GO 등급 선택. 정차 중 차량 화면이나 폰에서 설정 | — |
| GO 등급 | 무조건 GO / 웬만하면 GO / 가까우면 GO. 등급별 최대 우회 시간은 사용자 설정 (예: 30 / 15 / 5분) | — |
| 매칭 모드 자동 전환 | 내비가 경로 안내 중이면 경로 매칭, 목적지 없이 달리는 중이면 지역 매칭으로 바꾼다 | NaviHelper `onNavigationStatus` |
| 출발 전 브리핑 | 정차 중 목적지를 정하면 이번 경로 위 관심 매물과 제외 이유를 보여 준다. 여기서 고르면 판매자에게 미리 요청하고, 수락되면 목적지와 경유지를 한 번에 설정한다 | `getDestinationInfo`, `requestRouteWithWaypoints` |
| 경로 매칭과 우회 시간 | 서버가 목적지·현재 위치로 경로 선을 받아(외부 길찾기 API) 근처 매물을 고른다. 우회 시간 = 현재→매물(`requestTrip`) + 매물→목적지(외부 API) − 지금 목적지까지 남은 시간 | `getDestinationInfo`, `getCurrentLocationInfo`, `requestTrip` |
| 지역 매칭 | 목적지가 없으면 현재 위치가 매물 반경에 들어올 때 "여기서 N분 거리"만 안내한다 | `getCurrentLocationInfo`, `requestTrip` |
| 에너지 확인 | 전기차는 들렀다 가도 목적지 도착 배터리가 기준(예: 15%) 이상일 때만 알린다(계산식은 8-2). 내연기관은 주행 가능 거리로 같은 판단을 한다 | `requestTrip`(도착 배터리 예측), EvBattery, Fuel |
| 적재 판단 | 차종 → 트렁크 치수표와 매물 실측을 비교한다. 트렁크에 쏙 / 2열 접으면 가능 / 안 들어감(제외). 2열에 사람이 앉아 있으면 "2열 접으면 가능"도 제외 | CarInfo, Seat 착석 |
| 말할 때 고르기 | 회전 직전, 방향지시등을 켠 동안, 크게 조향하거나 제동하는 중에는 음성 알림을 미루고, 끝나면 말한다 | NaviHelper TBT, TurnSignal, SteeringWheel, Brake |
| 알림과 응답 | 한 번에 1개, 추천 1위만. 짧은 차임 뒤 "카시트, 12분 더, 트렁크에 쏙, 기준가보다 3만 원 싸요. 들를까요?" 말한 문장은 화면 아래 자막으로도 보인다. 대답은 정해진 단어("응/아니")로만, 말한 지 2초 뒤부터 6초 동안 받고 자막에 듣는 중과 알아들은 말을 표시한다. 정차 중에는 자막에서 다시 듣기 | Pleos TextToSpeech·SpeechToText(둘 다 ON_DEVICE, 안 되면 안드로이드 표준 TTS·음성 인식) |
| 경합 선택 | 점수가 비슷한 2개만 "카시트? 유모차?"로 묻는다 | 위와 같음 |
| 물건 요약 브리핑 | 운전 중엔 사진을 봐도 흠집을 알기 어렵다. 매물마다 판매자 글을 한두 문장으로 줄이고, 사진에서 보이는 흠집·손상·사용감을 짧은 항목으로 적어 둔다(AI 비전, 서버 키가 있을 때). 목록에서 고르면 정차 중엔 사진·요약·상태 카드, 주행 중엔 누르는 즉시 읽어 준다. 알림 카드에도 '사진: 흠집 안 보임' 한 칩. 사진 분석이 없으면 글 요약만 보여 주고 '사진 분석 없음'이라고 쓴다 | 서버(Claude 비전), TTS |
| 대화로 고르기 | 말로 묻고 말로 고른다. "카시트 흠집 있어?", "둘 중에 뭐가 더 싸?", "얼마나 돌아가?", "유모차로 할게". 조수는 지금 목록의 사실(가격·기준가·우회·적재·배터리·판매자·글 요약·사진에서 본 것·제외 이유)만으로 두 문장 안에 답하고 읽어 준다. 행동은 요청·고르기·거절 셋뿐이고 제외 매물은 요청하지 않는다. 서버에 AI 키가 있으면 Claude가, 없으면 규칙 조수가 같은 모양으로 답한다 | 마이크 = Pleos SpeechToText 자유 듣기(안 되면 안드로이드 SpeechRecognizer), Gleo ASK_ABOUT_LISTINGS, Pleos TTS |
| 차량 음성 비서(Gleo AI) | 앱을 열지 않고도 "주행중고에 유모차 관심 추가해 줘", "들를게", "주행중고에 카시트 흠집 있는지 물어봐" 같은 말을 Gleo가 알아듣고 앱 기능(관심 추가·알림 답하기·매물에 대해 묻기)을 부른다. 앱은 7초 안에 결과를 영어 문장과 데이터로 돌려주고, 묻기는 앱이 한국어로 직접 읽어 준다(Gleo엔 silent). 주행 중에는 화면을 열지 않고 말로만 | Gleo App Schema(`assets/schema.json`, actionCalls 3개, 공식 작성 규칙) + Intent·브로드캐스트 규약 |
| 경유지 추가와 확인 | 판매자가 수락하면 내비에 "주행중GO! 픽업 · 카시트"라는 이름으로 경유지를 넣고, 다시 조회해 실제로 반영됐는지 확인한다. 경유지가 이미 2개면 알리지 않는다 | `addWaypoint`, `getWaypointInfo` |
| 도착 공유 | 경유지까지 남은 시간으로 판매자에게 도착 예정 시각과 "나오세요"를 보내고, 도착 이벤트로 "도착했어요"를 보낸다 | `getWaypointInfo`(남은 시간), `onWayPointArrived` |
| 정차 판단 | 주행 제한 상태가 풀렸을 때만 상세 화면과 현장 확인 화면을 연다 | AAOS `CarUxRestrictionsManager` |
| 현장 확인 | 물건을 보고 "받았어요" 또는 "안 살게요(사유)". 사진은 거절한 뒤 폰에서 남긴다. 트렁크 열림·닫힘을 읽을 수 있으면 닫힌 순간 "실으셨나요?"를 먼저 띄운다 | Door(트렁크 상태, 확인 필요) |
| 판매자를 못 만났을 때 | 도착했는데 판매자가 안 보이면 "판매자에게 다시 알리기". 도착 5분 뒤에도 안 나오면 "판매자가 안 나왔어요"로 끝내고 전액 환불, 경유지 해제 | `removeWaypoint` |
| 돌아가기 | 거래 뒤 경유지가 남아 있으면 해제하고 원래 목적지로 이어 간다. 깨지기 쉬운 물건이면 "편안한 길로 바꿀까요?"를 묻는다 | `removeWaypoint`, `changeRouteOption(COMFORTABLE)` |
| 결과 카드 | 따로 다녀왔다면 걸렸을 시간과 실제로 늘어난 시간, 실제로 더 달린 거리. 판매자 평가(별 1~5) | 서버 계산, Odometer(확인 전에는 위치 누적 거리) |
| 개인화 카드 | "요즘 지나친 캠핑의자 같은 매물은 덜 알려 드릴게요" | — |
| 오류 처리 | 내비 오류(배터리 부족, 경로 탐색 실패 등)면 경유지를 넣지 않고 판매자 요청도 취소한다 | `onError(NaviErrorCode)` |

### 7-2. 판매자 모바일 웹

설치 없이 쓰는 모바일 웹으로 시작하고, 요청 알림은 웹 푸시로 보낸다. iOS는 홈 화면에 추가해야 웹 푸시를 받을 수 있어 출시 단계에서 앱 전환을 검토한다.

| 기능 | 설명 |
|---|---|
| 같이 올리기 | 다른 앱에 쓴 자기 글을 붙여 넣으면 제목·가격·설명을 채운다. 사진은 직접 고른다. 판매자 본인의 글과 사진만 옮긴다 |
| AI 크기 추정 + 실측 확인 | 사진에서 품목과 대략적인 크기를 채운다. 추정할 수 없으면 품목 대표 크기로 채우고 그렇게 표시한다. 큰 물건은 판매자가 실측을 확인해야 등록이 끝난다 |
| 알림 받기 | 웹 푸시로 페이지를 닫아 둬도 요청·곧 도착·도착·"구매자가 기다리고 있어요"를 받는다. HTTPS 주소에서만 되고, iOS는 홈 화면에 추가해야 한다 |
| 상태·사진 | 상태(상/중/하), 흠집 사진, 깨지기 쉬움 여부. 현장 확인의 기준이 된다 |
| 거래 가능 시간 | 평일 저녁·매일 저녁·주말 낮·언제든 중에 고르거나 요일·시간을 직접 정한다. 이 시간 밖에는 구매자에게 알리지 않는다. 장소·시간·자동 수락은 지난 등록을 기본값으로 쓴다 |
| 자동 수락 (선택) | 거래 가능 시간 안의 요청은 바로 확정한다 |
| 잠깐 쉬기 | 1시간·오늘은 그만·다시 켤 때까지. 그동안 내 물건은 지나가는 차에 보이지 않고 요청도 오지 않는다. 요청 화면에서 '오늘은 그만 받을래요'로 거절과 함께 고를 수 있다 |
| 지나간 차 수 | 물건마다 들를 수 있는 추천으로 보인 주행 수와 음성 알림 수. 누가 봤는지는 남기지 않는다 |
| 실시간 요청 수락 | "15분 뒤 도착 예정" 알림 → 수락/거절. 구매자가 우회 지점을 지나기 전까지 유효 |
| 진행 | 도착 예정 시각, 도착 몇 분 전 "나오세요", 도착하면 "도착했어요". 도착 3분 전부터는 폰 전체에 만남 화면(도착하면 구매자가 거래를 끝낼 수 있게 되기까지 남은 시간) |
| 지금 나가요 | 만남 화면에서 한 번 누르면 구매자 차에 "판매자가 나오고 있어요"가 뜬다. 채팅·전화는 없다 |
| 건넸어요·정산 | 건넨 뒤 구매자 확인 또는 일정 시간 뒤 정산 |
| 판매 완료 | 다른 곳에서 팔리면 바로 내린다 |

### 7-3. 거래 원칙과 구매자 보호

- 가격은 등록 가격 그대로 거래한다. 흥정은 없다.
- 결제 수단은 미리 등록해 둔다. 판매자가 수락하는 순간 대금을 결제 대행사(PG)의 에스크로에 보관한다. 운전 중 결제 조작은 없다.
- 현장에서 물건이 등록 정보(사진·실측·상태)와 다르면 구매자는 "안 살게요"를 고르고 사유와 사진을 남긴다. 대금은 전액 환불된다.
- 등록 정보와 같으면 구매자가 "받았어요"를 누르거나, 출발 후 일정 시간 동안 이의가 없으면 판매자에게 정산한다.
- 판매자 수락 전에는 구매자가 자유롭게 취소한다. 수락 후 구매자 취소와 노쇼는 신뢰도에 남고, 최근 30일에 3번이면 마지막 건부터 7일 동안 요청을 제한한다. 차 쪽 실패(내비 오류·경유지 실패)로 앱이 대신 취소한 건은 세지 않는다. 노쇼 보상금은 검토 중이다.
- 판매자가 수락 후 취소하거나 자리에 없으면 구매자에게 바로 알리고 경유지를 해제한다. 자리에 없을 때는 구매자가 다시 알릴 수 있고, 도착하고 5분을 기다려도 안 나오면 구매자가 거래를 끝낸다(전액 환불). 판매자 신뢰도와 노출 순위(8-2의 R)에 반영한다.
- 거래와 확인은 정차 상태에서만 진행한다.

### 7-4. 만들지 않는 것

| 하지 않는 것 | 이유 |
|---|---|
| 차 없는 구매자용 둘러보기·채팅·흥정 | 기존 중고 앱이 잘하는 영역이다. 만들수록 차에 있어야 할 이유가 흐려진다 |
| 다른 중고 플랫폼 매물 수집·연동 | 제휴 없이 매물을 긁어 오면 데이터베이스 권리·부정경쟁 문제가 생길 수 있고, 공모전 유의사항의 제3자 권리 조항과도 부딪힌다 |
| 도착 시 차 문 잠금 해제, 실내 조명 연출 | 차량 제어 SDK가 아직 제공되지 않는다. 낯선 장소에서 문이 자동으로 열리는 건 보안상 역효과다 |
| 다른 플랫폼 이름·로고를 앱 화면에 쓰기 | 제3자 권리 |

## 8. 추천 알고리즘 (초기안)

아래 수식과 가중치는 기획 단계의 **가정값**이며, 개발하면서 조정한다.

### 8-1. 제외 조건 (먼저 거른다)

- 우회 시간 > 해당 GO 등급의 최대 우회 시간
- 적재 판정 = 안 들어감, 또는 "2열 접으면 가능"인데 2열에 사람이 앉아 있음
- 들렀다 가면 목적지 도착 배터리가 기준 미만 (내연기관은 주행 가능 거리 부족)
- 도착 예정 시각이 판매자의 거래 가능 시간 밖
- 판매자가 이미 다른 거래를 수락했거나 매물이 판매 완료됨
- 내비 경유지가 이미 2개 (NaviHelper 경유지는 최대 2개)

### 8-2. 점수

```
score = 0.35·G + 0.20·W + 0.20·P + 0.25·D
score = score × M(카테고리) × R(판매자 신뢰)

우회 시간 = T(현재→매물) + T(매물→목적지) − T(현재→목적지)
  T(현재→매물):   NaviHelper requestTrip
  T(매물→목적지): 서버의 외부 길찾기 API
  T(현재→목적지): NaviHelper getDestinationInfo의 남은 시간

목적지 도착 배터리(전기차) ≈ S매물 − d(매물→목적지) × (S현재 − S매물) ÷ d(현재→매물)
  S현재:              Vehicle EvBattery
  S매물, d(현재→매물): NaviHelper requestTrip (도착 배터리 예측, 거리)
  d(매물→목적지):      서버의 외부 길찾기 API
  매물이 아주 가까우면 소비율이 흔들리므로 차종별 기본 소비율을 쓴다
```

| 기호 | 의미 | 값 |
|---|---|---|
| G | GO 등급 | 무조건 1.0 / 웬만하면 0.6 / 가까우면 0.3 |
| W | 찜 여부 | 찜한 매물 1.0 / 키워드 매칭 0.5 |
| P | 가격 매력도 | (기준가 − 가격) ÷ 기준가, 0~1로 자름 |
| D | 우회 부담 | 1 − (우회 시간 ÷ 등급 최대 우회 시간) |
| M | 개인화 배수 | 카테고리별 기본 1.0 |
| R | 판매자 신뢰 | 1 − 0.5 × (수락 뒤 취소·미응대·현장 불일치 ÷ (정산된 거래 + 그 건수)), 하한 0.5. 문제 거래가 없으면 1.0 |

**기준가:** 다른 플랫폼 시세는 쓰지 않는다. 초기에는 카테고리·사용 기간별 기준표를 직접 만들고(시연은 더미), 거래가 쌓이면 자체 거래 데이터로 바꾼다.

### 8-3. 경합 처리

1위와 2위의 점수 차가 0.1 미만이고 두 매물이 모두 무조건 GO 또는 웬만하면 GO이면 선택형 음성 질문을 한다. 대상은 2개까지이고, 운전 중 부담을 줄이려고 한 단어로 고를 수 있게 묻는다("카시트? 유모차?"). 고른 매물이 그날 1위가 된다.

### 8-4. 개인화 (지나친 매물)

- 추천을 받고 들르지 않고 지나친 매물은 부정 신호다. 별도의 "거절" 개념은 두지 않는다.
- 한 번 지나친 건 "오늘은 바빠서"일 수 있다. 같은 카테고리를 **서로 다른 날 2번 이상** 지나쳤을 때부터 M을 × 0.9 한다 (하한 0.5).
- 거래가 성사되면 M을 × 1.05 한다 (상한 1.2).
- 사용자별 가중치를 조정하는 방식이며, 모델을 다시 학습하지 않는다.

## 9. 사용자 플로우

1. (판매자) 다른 앱에 쓴 글을 붙여 넣고 사진을 고른다. AI가 크기를 채우면 실측을 확인하고, 상태·거래 가능 시간·자동 수락 여부를 정한다. 정확한 거래 지점은 수락 후에만 공개된다.
2. (구매자) 키워드나 찜으로 관심사를 저장하고 GO 등급과 결제 수단을 등록한다.
3. (구매자, 정차 중) 목적지를 정하면 출발 전 브리핑을 본다. 미리 들를 매물을 골라 둘 수 있다.
4. 주행 중 내비 상태에 따라 경로 매칭 또는 지역 매칭으로 후보를 찾고, 8장의 제외 조건과 점수로 1위를 고른다.
5. 회전·차선 변경 같은 순간을 피해 음성으로 알리고 "응"/"아니"를 받는다. 경합이면 2개 중 하나를 고르게 한다.
6. "응"이면 판매자에게 요청이 간다. 자동 수락 시간대면 바로 확정된다.
7. 판매자가 수락하면 대금이 보관되고 경유지가 추가된다. 우회 지점을 지날 때까지 응답이 없으면 자동 취소하고 다음 추천으로 넘어간다.
8. 판매자에게 도착 예정 시각이 가고, 도착 몇 분 전 "나오세요" 알림이 간다.
9. 도착하면 판매자에게 "도착했어요"가 간다. 차가 정차 상태가 되면 현장 확인 화면이 열린다.
10. 구매자가 물건을 확인한다. 같으면 싣고, 판매자가 "건넸어요", 구매자가 "받았어요". 다르면 "안 살게요"로 전액 환불된다.
11. 경유지를 해제하고 원래 목적지로 이어 간다. 결과 카드와 개인화 카드가 뜬다.
12. 이의가 없으면 판매자에게 정산하고 서로 평가한다.

## 10. 12월 시연 시나리오 (약 3분)

## 11. Pleos SDK 활용 설계

### 11-1. 원칙

1. **차를 움직이기보다 차를 읽는다.** Pleos SDK 사용 신청 페이지 기준(2026-11-02 확인), Vehicle State와 NaviHelper는 신청 없이 바로 쓸 수 있고 Vehicle Control, FusedLocation은 준비 중이다. TextToSpeech·SpeechToText는 11-04 확인한 문서(v3.3.1)대로 ON_DEVICE 모드를 등록 없이 쓴다. 핵심 기능은 바로 쓸 수 있는 조회 기능 위에 세운다.
2. **판단마다 근거 신호를 차에서 가져온다.** 들를 수 있나(경로·시간), 실을 수 있나(차종·좌석), 갔다 와도 되나(배터리), 지금 말해도 되나(회전·방향지시등·조향·제동)를 각각 차 신호로 판단한다.
3. **차종마다 다르게 동작해도 깨지지 않게 한다.** API 지원은 차종마다 다를 수 있어 도메인별 `check…Capabilities`로 먼저 확인한다. 없는 신호는 보수적으로 대체한다. 예를 들어 좌석 정보가 없으면 "2열 접으면 가능"을 묻는 방식으로 바꾼다.
4. **준비 중인 SDK는 같은 인터페이스 뒤에 둔다.** 음성 출력·음성 입력·위치를 인터페이스로 감싸 두었다. 음성 출력·입력은 Pleos TextToSpeech·SpeechToText로 바꿨고(안 되면 안드로이드 표준으로 내려감), 위치는 Pleos FusedLocation이 열리면 구현만 바꾼다.
5. **SDK 호출이 성공했다고 끝내지 않는다.** 경유지는 추가한 뒤 `getWaypointInfo`로 다시 조회해 실제 반영을 확인한 다음에 판매자에게 확정을 알린다.

### 11-2. 여정별 활용 지도

| 단계 | 차에서 읽는 것 | 판단 |
|---|---|---|
| 1. 모드 | NaviHelper 내비 상태 (`onNavigationStatus`: 경로 안내 / 자유 주행) | 경로 매칭 또는 지역 매칭 |
| 2. 후보 | 목적지·남은 시간 (`getDestinationInfo`), 현재 위치 (`getCurrentLocationInfo`) | 경로 근처 매물 (서버) |
| 3. 우회 | 매물까지 거리·도착 예정 (`requestTrip`), 현재 경유지 (`getWaypointInfo`) | 우회 시간, 경유지 여유 |
| 4. 에너지 | 매물 도착 시 배터리 예측 (`requestTrip`), 현재 배터리 (EvBattery), 연료 (Fuel) | 갔다 와도 되는지 |
| 5. 적재 | 차종 (CarInfo), 2열·3열 착석 (Seat) | 트렁크 / 2열 접기 / 제외 |
| 6. 말할 때 | 다음 회전까지 거리 (`onTBTInfo`), 방향지시등 (TurnSignal), 조향각 (SteeringWheel), 브레이크 페달 (Brake), 주행 제한 (CarUxRestrictions) | 알림 미루기, 화면 제한 |
| 7. 약속 | 경유지 추가 (`addWaypoint`, 출발 전이면 `requestRouteWithWaypoints`) → 재조회 (`getWaypointInfo`) | 반영 확인 후 판매자에게 확정 |
| 8. 만남 | 경유지 남은 시간 (`getWaypointInfo`), 도착 이벤트 (`onWayPointArrived`) | 판매자에게 도착 예정·"나오세요"·"도착했어요" |
| 9. 건네기 | 주행 제한 해제 (CarUxRestrictions), 트렁크 상태 (Door, 확인 필요) | 현장 확인 화면, "실으셨나요?" |
| 10. 마무리 | 주행거리계 (Odometer), 경로 옵션 (`changeRouteOption`) | 실제로 더 달린 거리, 깨지기 쉬운 물건이면 편안한 길 제안 |

시그니처는 공식 API 레퍼런스(Vehicle SDK 2.3.2, NaviHelper SDK 3.0.5)에서 확인했다. 런타임 동작은 에뮬레이터에서 아직 확인하지 않았다(11-5).

- NaviHelper에는 경로 선(폴리라인)이 없고, "여기 들르면 몇 분 더 걸리나" 같은 가정 경로 계산도 없다. 그래서 경로 근처 매물 찾기와 매물→목적지 시간은 서버가 외부 길찾기 API로 계산한다.
- 외부 길찾기 API 호출은 경로당 한 번(경로 선)과 후보 매물별 한 번(매물→목적지)으로 줄인다. 현재→매물 시간은 차 안의 `requestTrip`으로 구한다.
- 퍼미션 이름은 Vehicle SDK 퍼미션 문서와 NaviHelper 레퍼런스 기준이다. 퍼미션은 Pleos App Market과 사전 협의된 범위 안에서만 쓸 수 있다.
- 구현(차량 앱 셸)은 시그니처까지 확인한 API만 직접 부른다. CarInfo 모델명·Odometer·Fuel·Door·RouteInfo(목적지 설정)는 확인 전까지 대체 경로로 동작한다: 차종은 처음 한 번 선택, 더 달린 거리는 현재 위치 누적, 목적지는 Pleos 내비에서 설정. 자세한 현황은 `docs/API_MATRIX.md`.

### 11-4. 쓰지 않는 것

| API | 이유 |
|---|---|
| Door 잠금 해제, Light 앰비언트 연출 | 차량 제어 SDK 준비 중. 낯선 장소에서 문이 자동으로 열리는 건 보안상 역효과고, 조명은 장식에 가깝다 |
| AAOS `VehiclePropertyIds` 직접 접근 (모델명 등) | 문서상 Pleos 기술지원 검토 요청이 필요하다. CarInfo에 모델명이 없으면 처음 한 번 사용자가 차종을 고른다 |
| 주차 브레이크·기어·속도 | Vehicle SDK에 없다 (Brake는 페달 상태만). 정차는 `CarUxRestrictionsManager`로 판단한다 |

### 11-5. 에뮬레이터 확인 항목 (미실행)

| # | 확인할 것 | 안 될 때 |
|---|---|---|
| 1 | `requestTrip`이 내비 안내를 바꾸지 않는지, eta 단위, 등록되지 않은 지점도 되는지 | 서버의 외부 API로 현재→매물 시간까지 계산 |
| 2 | `addWaypoint`가 임의 좌표로 되는지, 추가 뒤 `getWaypointInfo`로 확인되는지 | 판매자 지점을 잠시 목적지로 설정(`requestRoute`)하고, 거래 뒤 원래 목적지로 다시 설정 |
| 3 | `onTBTInfo` 갱신 주기와 다음 회전까지 거리 | 방향지시등·조향각만으로 알림 타이밍 판단 |
| 4 | Seat·TurnSignal·SteeringWheel·Brake·EvBattery가 Virtual Console 조작에 반영되는지 | 시연은 서버 더미 신호로 보여 주고 "실제 연동 아님"을 화면에 표시 |
| 5 | CarInfo에 모델명이 있는지 | 처음 한 번 사용자가 차종 선택 |
| 6 | Door 도메인에서 트렁크 열림을 읽을 수 있는지 | "실으셨나요?" 없이 현장 확인 화면만 |
| 7 | Fuel 도메인에 주행 가능 거리가 있는지 | 내연기관은 에너지 확인 생략 |
| 8 | Pleos TTS(`ON_DEVICE` 한국어)가 동작하는지, 안 되면 안드로이드 표준 TTS·음성 인식이 되는지 | 화면 알림 + 큰 버튼 하나 |
| 9 | `CarUxRestrictionsManager` 값이 기어 P/D에 따라 바뀌는지 | 정차 시연만 하고 상세 화면은 정차 표시 뒤에만 |
| 10 | 목적지 없이 달릴 때도 `getCurrentLocationInfo`가 오는지 | 안드로이드 표준 위치 API |

## 14. 안전·개인정보 설계

- 주행 중에는 음성만 쓰고, 알림은 한 번에 1개만 보낸다. 회전 직전, 방향지시등을 켠 동안, 크게 조향하거나 제동하는 중에는 말을 걸지 않는다.
- 화면은 `CarUxRestrictionsManager`의 주행 제한 상태를 따른다. 음성 인식을 쓸 수 없으면 주행 중에는 알림만 하고, 결정은 출발 전 브리핑과 정차 후로 미룬다.
- 상세 화면, 거래, 확인은 정차 상태에서만 열린다. "주행 중 거래" 앱으로 오해받지 않도록 기획안과 시연에서 명시한다.
- 들렀다 가면 배터리나 연료가 부족해지는 매물은 알리지 않는다.
- 거래 지점은 정차할 수 있는 곳만 지정할 수 있다.
- 차 문 자동 해제 같은 차량 제어는 하지 않는다.
- 판매자의 정확한 거래 지점은 수락 후에만 공개한다. 판매자에게는 구매자의 실시간 위치가 아니라 도착 예정 시각만 보낸다. 전화번호는 서로 공개하지 않는다.

## 16. 사업성

**타깃 고객**
- 구매자: Pleos Connect 차량으로 매일 출퇴근·출장하는 운전자. 큰 물건 수요가 생기는 시기(육아, 캠핑, 이사)의 운전자를 먼저 겨냥한다.
- 판매자: 큰 물건을 팔려는 개인. 차 유무와 상관없다.

**사용자 확보**
- 판매자는 기존 앱을 그만둘 필요 없이 같이 올린다. 자기 글을 붙여 넣고 크기만 확인하면 끝나서 추가 비용이 거의 없다.
- 구매자는 Pleos App Market에서 설치한다. 백그라운드에서 동작해 켜 두지 않아도 된다.
- 한 구간에서 매물과 구매자 밀도를 먼저 만든 뒤 넓힌다.

**지속 이용 (Retention)**
- 출퇴근 경로는 매일 반복돼서 앱을 열지 않아도 알림이 생긴다.
- 출발 전 브리핑이 목적지를 정할 때마다 앱을 여는 계기가 된다.
- 판매자는 한 번 팔아 본 뒤 다음 큰 물건도 같은 방식으로 올린다.

**예상 MAU (산식과 1차 추정 — 가정을 적어 두고 설문·실데이터로 바꾼다)**
- 구매자 MAU = 대상 구간의 Pleos 탑재 차량 수 × 설치율 × 월 활성률
- 판매자 MAU = 월 신규 등록 판매자 + 재등록 판매자
- 모수: 플레오스 커넥트는 더 뉴 그랜저(2026.5~)·디 올 뉴 아반떼(2026.7~)에 먼저 실리고 4분기 투싼, 2027년부터 기아 전 차종으로 넓힌다(전자신문 2026-07-24). 2026년 9월 국내 판매 그랜저 8,898대·아반떼 7,305대(현대차 월 판매 자료, 2026-10-01 보도) → 두 차종만으로 월 약 1만 6천 대, 1년 누적 약 19만 대.
- 1차 추정(국내, 출시 12개월): 탑재 차량 약 20만 대 × 설치율 5~10% × 월 활성률 30~50% = 구매자 MAU 약 3천~1만. 2027년 기아 확대·투싼 포함 시 모수가 몇 배로 는다. 판매자는 구매자 알림이 닿는 구간(수도권 출퇴근 축)에서 월 수백 명으로 시작.
- 설치율·활성률은 가정이다. 아래 설문(허용 우회 시간, 큰 물건 구매 의향)과 출시 뒤 실데이터로 바꾼다.

**검증 계획 (11/15 전)**
- 큰 물건을 팔아 본 사람 10명 이상: "차 있으세요/들어가요" 문답, 노쇼, 흥정을 겪었는지, 여기에도 같이 올리겠는지
- 차로 출퇴근하는 사람 10명 이상: 동네 밖 매물을 가는 길에 살 의향, 허용 우회 시간

**수익 모델 (초기안, 확정 전)**
- 성사된 거래에 수수료. 초기 확산 기간에는 받지 않는다.
