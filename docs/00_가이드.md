## 1. 이 프로젝트는 무엇인가

- **목표:** 현대차·기아 「차량용 앱 개발 공모전」 출품 (1차 서류 → 2차 PT 시연)
- **서비스명:** 주행중GO! (주행 중 + 중고 + GO)
- **한 줄 정의:** 찜해 둔 중고 매물이 운전 경로나 지나는 지역에 있으면 알려 주고, 경유지 추가부터 판매자 수락까지 차 안에서 끝내는 차량용 중고 거래 앱
- **핵심 메시지**
  - 구매자: 좋은 매물은 동네 밖에도 있다. 동네 반경이 아니라 매일 지나는 길을 탐색 범위로 쓴다.
  - 판매자: 실을 수 있는 차만, 집 앞까지, 약속하면 반드시 오는 구매자. 우리 동네를 지나가는 사람에게까지 보인다.
- **공모 분야:** 모빌리티 & 라이프 편의 (공식 설명: "주행 중에도 끊김 없는 주문 · 픽업 · 주차 등 일상 서비스 경험")

| 에너지 확인 | 전기차는 들렀다 가도 목적지 도착 배터리가 기준(예: 15%) 이상일 때만 알린다 |
| 경합 처리 | 최대 2개, 한 단어로 고르게 묻는다 |
| 개인화 | 같은 카테고리를 서로 다른 날 2번 이상 지나쳤을 때부터 가중치를 낮춘다. 모델 재학습이 아니다. "거절" 개념은 두지 않는다 |
| 판매자 수락 | 실시간 수락 + 거래 가능 시간 + 자동 수락(선택). 우회 지점 통과 전 응답이 없으면 자동 취소 |
| 가격 | 등록 가격 그대로. 흥정 없음. 기준가는 자체 기준표로 시작해 자체 거래 데이터로 바꾼다 |
| 적재 판단 | 사진 AI 크기 추정(서버에 키가 있을 때, 없으면 품목 대표 크기로 채우고 그렇게 표시) + 큰 물건은 판매자 실측 확인 + CarInfo 차종 → 트렁크 치수표. 2열 착석이면 "2열 접으면 가능" 제외. 3열 차는 3열 세움 → 3열 접기 → 2·3열 접기 순서로 보고 3열 착석이면 접는 칸 제외(Seat ROW_3_LEFT·RIGHT만, ROW_3_CENTER 미확인) |
| 사진 크기 추정 엔진 | Claude 비전(`claude-haiku-5-5`, `JHGO_AI_MODEL`로 바꿈). API 키는 서버에만 둔다. JPEG·PNG·WebP 사진만 보내고 샘플 그림은 보내지 않는다 |
| 정차 판단 | AAOS `CarUxRestrictionsManager`. Brake는 페달 정보뿐이라 정차 판단에 쓰지 않는다(알림 타이밍에만 쓴다) |
| 음성 | Pleos TextToSpeech(10-22 확인)와 SpeechToText(11-04 문서 확인, v3.3.1) 둘 다 ON_DEVICE·ko-KR로 쓴다(앱 등록 불필요). 인터페이스 뒤에 안드로이드 표준 TTS·음성 인식을 대체로 두어 초기화 실패나 NOT_SUPPORTED_API 같은 오류면 내려간다. 안 되면 주행 중엔 알림만. 차 화면은 말한 문장을 자막(알약)으로도 보여 주고, 알림 2초 뒤 6초 동안 정해진 말("응/아니", 품목 이름)만 듣는다. 알아들으면 자막에 '"카시트" — 알아들었어요'. 시뮬레이터(체험 페이지·녹화)는 마이크가 막혀 있어도 듣는 시간을 그대로 두고 가상 콘솔 '음성 대답' 버튼이 마이크 대신 말을 넣는다(실제 SDK 모드에는 없는 개발 도구) |
| 결제 | 판매자 수락 시 PG 에스크로 보관 → 현장 확인 → 정산. 트렁크 개폐 자동결제는 **확장 기능** |
| 결제 수단 등록 | 실서비스는 PG 결제창에서 카드를 등록하고 우리는 빌링 키만 받는다. 이 앱은 카드 번호를 받지 않는다. 시연은 '테스트 결제 수단(실제 결제 없음)'만. 결제 수단이 없으면 알림을 띄우지 않고 요청을 막는다 |
| 판매자 채널 | 설치 없는 모바일 웹 + 웹 푸시(서비스 워커·VAPID, HTTPS 필요). iOS는 홈 화면에 추가해야 받는다 → 출시 단계에서 앱 검토 |
| 구매자 폰 | 차 밖에서 하는 일만: 결제 수단, 거래 내역·판매자 평가, 현장 사진, 관심사. 둘러보기·채팅·흥정은 여전히 만들지 않는다 |
| 판매자 미응대 | 도착 뒤 구매자가 '판매자에게 다시 알리기'(1분에 한 번)를 할 수 있고, **도착 5분 뒤**부터 '판매자가 안 나왔어요'로 끝낼 수 있다 → 전액 환불, 경유지 해제, 판매자 신뢰도(noShow). 판매자가 '건넸어요'를 누른 뒤에는 못 쓴다 (기획서에 시간이 없어 정함) |
| 요청 제한 | 수락 뒤 구매자 취소·노쇼가 **최근 30일 3번**이면 **마지막 건부터 7일** 요청을 막는다. 차 쪽 실패(system 취소)와 수락 전 취소는 세지 않는다 (기획서에 기준이 없어 정함) |
| 판매자 신뢰(노출 순위) | 추천 점수에 R = 1 − 0.5 × (수락 뒤 취소·미응대·현장 불일치 ÷ (정산된 거래 + 그 건수))를 곱한다(하한 0.5). 응답률 30% 미만(요청 3건 이상)은 알리지 않는다 |
| 판매자 쉬기 | 1시간 / 오늘은 그만(자정까지) / 다시 켤 때까지. 쉬는 동안 그 판매자의 매물은 매칭에서 빠지고 요청은 거절된다(진행 중 거래는 그대로). 요청 화면 '오늘은 그만 받을래요' = 거절 + 오늘 쉬기 |
| 지금 나가요 | 판매자가 만남 화면에서 한 번 누르는 정해진 신호. 구매자 차에 '판매자가 나오고 있어요'. 채팅·전화번호 교환은 여전히 만들지 않는다. 5분 기다림 규칙은 바꾸지 않는다 |

## 5. Pleos API에서 확인한 사실 (공식 문서 기준)

- **Pleos Connect SDK 모듈:** Vehicle, NaviHelper, TextToSpeech, SpeechToText, FusedLocation
- **SDK 제공 상태 (2026-11-02, SDK 사용 신청 페이지):** Vehicle State와 NaviHelper는 신청 없이 바로 사용. Vehicle Control, FusedLocation, SpeechToText, TextToSpeech는 준비 중(신청 버튼 없음).
- **Vehicle SDK 도메인:** Brake, CarInfo, Display, Door, DrivingMode, EvBattery, Fuel, HVAC, Light, Odometer, Safety, Seat, SideMirror, Steeringwheel, Tire, Toll, TurnSignal, Window, Wiper
- **퍼미션:** 조회 `pleos.car.permission.CAR_*`, 제어 `CONTROL_CAR_*`. App Market과 사전 협의·승인된 범위만 쓸 수 있다.
- **레퍼런스에서 시그니처를 확인한 것 (Vehicle 2.3.2):** SteeringWheel 전륜 조향각 리스너(CAR_DRIVE), Brake 페달 상태(CAR_DRIVE), TurnSignal 상태 OFF/LEFT/RIGHT(CAR_LIGHTS), Seat 착석 `registerSeatOccupancy` ROW_1_LEFT~ROW_3_RIGHT(CAR_SEATS), EvBattery 충전량 %(CAR_ENERGY), 도메인별 `check…Capabilities`.
- **없는 것:** 기어·속도·주차 브레이크 API (Brake는 페달 상태만). 주행 제한은 AAOS `CarUxRestrictionsManager`로 판단. AAOS `VehiclePropertyIds` 직접 접근은 문서상 Pleos 기술지원 검토 요청이 필요하다.
- **CarInfo:** 외부 크기, 제조사, 연식. 트렁크 용량은 없다. 모델명 제공 여부는 확인 필요.
- **트렁크 개폐:** Vehicle Data API(클라우드) 웹훅 `Trunk.Open`과 Virtual Console에서 확인. 차량 안 SDK(Door)로 읽히는지는 미확인.
- **NaviHelper 3.0.5:** `getDestinationInfo`(좌표·남은 거리·남은 시간), `getCurrentLocationInfo`, `getWaypointInfo`(남은 거리·시간), `addWaypoint`(최대 2개, NAVI_ROUTE_SEARCH), `removeWaypoint`, `requestRouteWithWaypoints`, `requestTrip`(현재 위치→지점 거리·eta·도착 배터리 예측, NAVI_ROUTE), `getTBTInfo`(다음 회전), `changeRouteOption`(COMFORTABLE 등), `onNavigationStatus`(FREE_DRIVE/ROUTE_DRIVE 등), `onWayPointArrived`, `onError(NaviErrorCode)`. **경로 선(폴리라인)과 가정 경로 계산은 없다** → 매물에서 목적지까지 시간은 서버가 외부 길찾기 API로 계산.
- **TextToSpeech:** 레퍼런스(`ON_DEVICE`, ko-KR, TTS_SERVICE)와 Maven 좌표는 문서에 있지만 사용 신청은 준비 중.
- **API 지원은 차종마다 다를 수 있다.** 도메인별 `check…Capabilities`로 확인한다.
- **없거나 못 찾은 것:** 무게 센서, 결제 API, 실내 카메라
- 문서: https://document.pleos.ai/docs/pleos-only/connect-sdk-pleos/ · SDK 제공 상태: https://document.pleos.ai/docs/pleos-only/create-my-project

## 6. 시연에서 쓰는 API

- **NaviHelper:** 내비 상태, 목적지·현재 위치, `requestTrip`, TBT, 경유지 추가·재조회, 남은 시간, 도착 이벤트
- **Vehicle:** CarInfo, Seat 착석, EvBattery, TurnSignal, SteeringWheel, Brake(알림 타이밍), Odometer
- **AAOS:** `CarUxRestrictionsManager`
- **음성:** 안드로이드 표준 TTS·음성 인식 (Pleos TTS가 에뮬레이터에서 되면 그쪽)
- **쓰지 않는 것:** Door 잠금 해제, Light 앰비언트. Vehicle Data API는 확장 기능(트렁크 자동결제)에서만 쓴다.

## 7. 시연 시나리오 요약

"금요일, 수원 출장 마치고 송파 집으로 퇴근 중"인 김주행(가명, 전기 SUV). 카시트와 유모차는 무조건 GO, 아기 침대는 웬만하면 GO, 캠핑의자는 가까우면 GO로 찜해 두었다.
판매자 박서연(가명)이 폰으로 카시트를 같이 올린다 → 정차 중 출발 전 브리핑, 2열 착석을 켜면 아기 침대가 빠진다 → 영통 근처에서 차선 변경이 끝난 뒤 캠핑의자 알림, 지나친다 → 판교 근처에서 카시트와 유모차가 경합해 "카시트? 유모차?" → 카시트를 골라 판매자가 폰으로 수락, 대금 보관, 내비에 픽업 경유지 표시 → 도착 예정·"나오세요"·"도착했어요" → 정차 후 현장 확인, 건넸어요·받았어요 → 경로 이어 가기, 결과 카드와 개인화 카드.
자세한 내용은 `01_기획서.md` 10장에 있다.

## 9. 경쟁·선행 사례 (차별성 근거)

- 경로상 **매장** 픽업은 이미 있다: GM Marketplace(2017), Concardis & IAV Automotive Marketplace, Xevo Market(현대차와 데모), eBay 특허 US9679325B2.
- **개인 간 중고 + 판매자 실시간 수락 + 경로·적재 매칭**을 결합한 사례는 검색 범위에서 찾지 못했다. 세상에 없다는 보장은 아니다.
- 당근은 동네 범위 기반이다. 2026년 3월 택배 거래('바로구매') 매물만 전국 검색으로 넓혔고, 직거래 매물은 동네 범위 그대로다. 경로 기반 알림은 확인되지 않았다.
- 번개장터는 전국에 노출되지만, 큰 물건 직거래는 거리가 걸림돌이다.
- 다른 플랫폼 매물을 크롤링하면 법적 위험이 있다 (야놀자 vs 여기어때: 형사 무죄, 민사 1·2심 10억 원 배상).
